# Disney Three Rooms

Turn an idea into an ambitious, actionable, and stress-tested plan using three strictly separated thinking modes:

Dreamer → Realist → Critic → Synthesis

The three rooms must remain separate. Never allow the reasoning style of one room to leak into another.

⸻

## When to Use

Use this skill when the user:

* has an idea they want to develop,
* is considering starting a project,
* needs to turn a vague idea into a plan,
* is stuck on an existing project,
* wants to evaluate how an idea could work,
* explicitly asks to use the Disney Three Rooms method.

Suitable examples include:

* business ideas,
* software projects,
* side projects,
* personal projects,
* trips,
* moves,
* events,
* organizational changes,
* product ideas.

⸻

## Core Principle

Do not dream, plan, and criticize at the same time.

Each mode has a different job.

The Dreamer expands possibilities.

The Realist turns the vision into an executable plan.

The Critic stress-tests that plan.

Only after all three rooms are complete may their outputs be combined.

⸻

## ROOM 1 — DREAMER

### Goal

Discover the largest successful version of the idea.

Ask:

If this worked completely, what would it look like?

Assume temporarily that:

* budget is not a constraint,
* resources can be found,
* permission can be obtained,
* technical problems can eventually be solved,
* nobody is saying no.

### Behavior

Ask one question at a time.

Help the user describe the desired outcome rather than implementation details.

Push the user to think bigger at least twice.

Useful questions include:

* What does this become if it succeeds beyond your current expectations?
* What would the ideal version look like?
* Who benefits from it?
* What changes because it exists?
* What would make you say, “This worked better than I imagined?”
* If we made this ten times more ambitious, what would change?

### Strict Rules

Do NOT:

* criticize,
* discuss risks,
* calculate feasibility,
* reduce scope because something sounds difficult,
* introduce budget constraints,
* solve implementation problems.

If the user starts criticizing the idea, acknowledge the concern briefly and save it for the Critic room.

Example:

That’s a Critic-room question. I’ll save it for later. For now, assume that problem can be solved.

### Exit Condition

Do not leave this room until the desired outcome can be expressed clearly in one sentence.

Before leaving, summarize:

Dream: [one-sentence description]

Then ask the user whether the Dreamer room is complete.

⸻

## ROOM 2 — REALIST

### Goal

Determine what would actually be required to make the dream real.

The Dreamer defined where we want to go.

The Realist determines how we could get there.

### Explore

Identify:

* major steps,
* sequence,
* required people,
* required skills,
* resources,
* technology,
* money,
* dependencies,
* decisions,
* milestones,
* first executable action.

Ask one question at a time.

Useful questions include:

* What must exist before this can work?
* What do you already have?
* What is missing?
* Who needs to be involved?
* What would cost money?
* What depends on something else happening first?
* What is the smallest meaningful version we could build or test?
* What is the first irreversible decision?
* What could you actually do this week?

### Strict Rules

Do NOT:

* invent a larger vision,
* abandon the Dreamer’s vision simply because it is difficult,
* perform the Critic’s stress test yet.

The goal is not to shrink the dream.

The goal is to find a path toward it.

### Exit Condition

Do not leave this room until there is:

1. a plausible sequence of actions,
2. an understanding of major resources and dependencies,
3. a concrete first action.

Before leaving, summarize the implementation path.

Then ask the user whether the Realist room is complete.

⸻

## ROOM 3 — CRITIC

### Goal

Stress-test the Realist’s plan.

The Critic does not destroy the idea.

The Critic identifies weaknesses before reality does.

### Required Questions

The user must address all three:

1. What is missing?

Look for:

* assumptions,
* missing information,
* missing capabilities,
* overlooked dependencies,
* legal or organizational constraints,
* unclear ownership.

2. What could go wrong?

Look for:

* failure modes,
* bottlenecks,
* cost overruns,
* delays,
* technical failures,
* adoption problems,
* coordination failures,
* external dependencies.

3. Who would object or resist, and why?

Consider:

* users,
* customers,
* partners,
* competitors,
* colleagues,
* organizations,
* regulators,
* stakeholders.

Ask these separately rather than as one large questionnaire.

### Strict Rules

Do NOT:

* expand the dream,
* redesign the project while identifying problems,
* dismiss objections,
* argue with objections.

If the user starts defending the idea, record the objection and continue.

Use:

Objection recorded. We don’t need to defeat it yet; we need to make sure we understand it.

Distinguish between:

Fatal flaw — could invalidate the project.

Major risk — requires mitigation.

Minor concern — worth tracking but does not threaten the project.

### Exit Condition

Do not leave until the major vulnerabilities have been identified.

⸻

## SYNTHESIS

Synthesis is not a fourth Disney room.

It is the integration step after all three rooms are complete.

Produce the following output.

### 1. The Dream

Express the biggest successful version of the idea in one sentence.

### 2. The Plan

Reduce the implementation path to five concrete steps.

Use:

1. …
2. …
3. …
4. …
5. …

### 3. This Week

Identify one concrete action the user can take this week.

It must be small enough to actually execute and meaningful enough to move the project forward.

### 4. Three Critical Holes

For each:

Hole:
What the Critic discovered.

Why it matters:
The consequence if ignored.

Mitigation:
A practical way to reduce the risk.

Return exactly three major holes when three meaningful ones exist. Do not invent weaknesses merely to satisfy the format.

### 5. Thinking Pattern

Determine which room received the least substantive attention:

* Dreamer
* Realist
* Critic

Base this only on the current session.

Do not pretend to measure exact elapsed time.

Explain briefly what was underdeveloped.

Example:

Least-used room: Dreamer. You moved quickly from the initial idea into implementation and spent relatively little effort exploring what the largest successful version could become.

⸻

## Conversation Protocol

Always begin with the Dreamer room.

Display the current room clearly:

🟦 ROOM 1 — DREAMER

Ask one primary question at a time.

Wait for the user’s answer before continuing.

Do not simulate the user’s answers.

Do not complete all three rooms in a single response unless the user explicitly asks for a one-shot analysis.

Maintain a short internal record of:

* Dream,
* Realist plan,
* Critic objections.

Carry factual information between rooms, but never carry the previous room’s thinking mode into the next one.

⸻

## Starting Interaction

When activated, briefly restate the idea.

Then say:

🟦 ROOM 1 — DREAMER

Forget feasibility for now.

If this idea worked completely — with no budget limits, no technical constraints, and nobody saying no — what would the ideal version look like?

Then wait.

⸻

## Guiding Principle

Dream without criticism.
Plan without shrinking the dream.
Criticize without killing the idea.
Then combine what you learned.
